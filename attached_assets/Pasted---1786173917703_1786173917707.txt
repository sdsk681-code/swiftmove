آه، الآن فهمت المطلوب بالضبط. أنت لا تريد منه يغيّر التصميم أو الوظائف؛ تريد منه يعمل تنظيف وترتيب للمشروع الحالي بنفس أسلوب التنظيم الظاهر بالصور، ويتأكد أن كل شيء يظل يعمل.

انسخ له هذا النص كما هو:

أريد منك إعادة تنظيم وتنظيف المشروع بالكامل بدون تغيير التصميم أو الواجهات أو الـ UI أو منطق العمل.

المشروع الحالي مبني بـ Next.js + React + TypeScript، لذلك لا تقم بتحويله إلى Vite أو React مختلف، وحافظ على الـ framework الحالي.

المطلوب:

1. افحص المشروع بالكامل أولاً، بما في ذلك:
    * app
    * components
    * hooks
    * lib
    * public
    * attached_assets
    * ملفات الإعدادات
    * API routes / server functions
    * package.json
    * tsconfig
    * ملفات البيئة
2. أنشئ هيكل ملفات واضح ومنظم مشابه لهذا الأسلوب:

project/
├── app/
│   ├── admin/
│   ├── api/
│   ├── check/
│   ├── compar/
│   ├── cookies/
│   ├── home-new/
│   ├── insur/
│   ├── privacy/
│   ├── step2/
│   ├── step3/
│   ├── step4/
│   ├── step5/
│   ├── step6/
│   ├── globals.css
│   ├── layout.tsx
│   ├── page.tsx
│   └── sitemap.ts
│
├── components/
│   ├── ui/
│   └── ...
│
├── hooks/
│   └── ...
│
├── lib/
│   ├── firebase/
│   ├── ...
│   └── ...
│
├── public/
├── attached_assets/
├── .github/
├── package.json
├── tsconfig.json
├── next.config.*
├── eslint.config.*
└── README.md

هذا مجرد تنظيم مقترح، لا تنقل أي ملف إلا بعد التأكد من استخداماته وImports الخاصة به.

3. ابحث عن الملفات المكررة مثل:
    * next.config.js و next.config.ts
    * postcss.config.js و postcss.config.mjs
    * أي ملفات Firebase مكررة
    * أي utilities أو components تؤدي نفس الوظيفة
    * أي صفحات أو routes مكررة
    لا تحذف أي ملف لمجرد أنه يبدو مكررًا. افحص الـ imports والاستخدامات أولاً، ثم احتفظ بالنسخة الصحيحة واحذف غير المستخدمة فقط.
4. ابحث عن الملفات القديمة أو التجريبية أو المؤقتة أو التي لا يتم استخدامها، واحذفها فقط بعد التأكد أنها غير مرتبطة بالمشروع.
5. نظّف الـ imports:
    * احذف imports غير المستخدمة.
    * أصلح المسارات بعد نقل الملفات.
    * استخدم aliases الموجودة بالمشروع إذا كانت معرفة مثل @/.
6. افحص package.json:
    * احذف dependencies غير المستخدمة فقط بعد التأكد.
    * لا تغيّر إصدارات الحزم بدون سبب.
    * لا تضف مكتبات جديدة إلا إذا كانت ضرورية.
    * استخدم package manager واحد فقط للمشروع.
7. افحص إعدادات Next.js وTypeScript وESLint وPostCSS وتأكد أنه لا يوجد تعارض بين ملفات الإعدادات.
8. افحص جميع الـ API routes وخصوصًا مسارات الحجز وtRPC، وتأكد أن ترتيب الملفات الجديد لا يكسرها.
9. افحص متغيرات البيئة:
    * لا تضع أي secrets داخل الكود.
    * لا تحذف أي environment variable مستخدم.
    * إذا كان هناك .env أو .env.local، اجعل استخدامها واضحًا وصحيحًا.
10. بعد انتهاء التنظيف، شغّل:

pnpm install
pnpm run build

ثم أصلح كل أخطاء TypeScript / Next.js / ESLint / build الناتجة عن إعادة التنظيم.

11. شغّل المشروع وتأكد أن الصفحات الأساسية تعمل، خصوصًا:

* الصفحة الرئيسية
* خطوات الحجز
* /book
* API routes
* tRPC
* Firebase
* الدفع

12. مهم جدًا: لا تغيّر أي تصميم، ألوان، خطوط، spacing، animations، نصوص، صور، layout أو UX. المطلوب فقط تنظيف وتنظيم الكود والملفات وإصلاح الأخطاء.
13. قبل حذف أي شيء مهم، اعمل فحصًا للـ references/imports حتى لا تتسبب في كسر المشروع.
14. في النهاية أعطني تقريرًا واضحًا يحتوي:

* الملفات التي تم نقلها.
* الملفات المكررة التي تم حذفها.
* الملفات غير المستخدمة التي تم حذفها.
* الأخطاء التي تم إصلاحها.
* dependencies التي تم تنظيفها.
* نتيجة pnpm run build.
* أي مشاكل متبقية.

الأولوية: الحفاظ على المشروع كما هو وظيفيًا وبصريًا، مع جعله مرتبًا ونظيفًا وسهل الصيانة. لا تقم بإعادة كتابة المشروع من الصفر.

والأهم عندك: لا تخليه يحذف next.config.js أو next.config.ts أو ملفات الإعدادات المكررة مباشرة؛ لازم يعرف أولًا أي واحد فعليًا مستخدم، لأن المشكلة التي ظهرت عندك سابقًا أصلًا فيها تعارضات وإعدادات بيئة/تشغيل.
